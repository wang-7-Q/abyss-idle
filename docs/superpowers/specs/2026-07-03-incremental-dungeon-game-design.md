# 暗黑刷宝增量游戏设计文档

## 概述

本项目要制作一款跨端增量地下城游戏：电脑端以网页形式运行，手机端以 App 形式运行。第一版使用同一套 Web 代码，先完成可玩的网页 MVP；网页版本稳定后，再通过 Capacitor 封装为手机 App。

游戏类型是暗黑刷宝风格的放置战斗游戏。角色会自动战斗，玩家也可以点击怪物、释放主动技能来加速推进。MVP 是纯前端单机游戏，不做服务器和账号系统；存档使用本地保存，并支持导入/导出存档码，实现跨设备迁移。

## 目标

- 做出可玩的核心循环：战斗、掉落、升级、装备、推进地下城。
- 第一版就兼顾电脑和手机布局。
- 游戏核心逻辑独立于 UI，方便测试公式、掉落、存档和离线收益。
- MVP 不做后端、账号、支付、排行榜、云同步。
- 为后续扩展暗黑词条、传奇特效、云存档、手机 App 打包保留结构空间。

## 非目标

- 不做多人玩法和联网经济系统。
- MVP 不做账号系统或云存档。
- 不做付费、广告、战令或商城。
- 不做复杂剧情战役。
- 第一版不做完整暗黑式打造、洗练、套装和传奇特效。

## 目标平台

- 电脑端：网页游戏。
- 手机端：由同一套 Web 代码封装出的 App。
- 第一阶段目标：完成响应式网页 MVP。
- App 打包目标：网页 MVP 稳定后接入 Capacitor。

## 核心玩法循环

1. 玩家进入当前地下城层数。
2. 角色自动攻击当前怪物。
3. 玩家可以点击怪物或释放主动技能造成额外伤害。
4. 怪物死亡后掉落金币、经验和少量装备。
5. 玩家用金币和经验成长提升角色属性。
6. 玩家替换更强装备。
7. 战力提升后推进更深地下城。
8. Boss 层作为进度门槛，击败后解锁更高收益区间。

核心体验应当是：伤害变高，怪死更快，掉落更好，玩家能推到更深层。

## 战斗系统

战斗是实时但轻量的。玩家始终面对一个当前敌人。角色会按照攻击力和攻速自动攻击。玩家点击敌人时造成额外伤害，让电脑鼠标操作和手机触摸操作都有主动参与感。

敌人的生命和奖励由地下城层数决定。Boss 在固定层数出现，例如每 10 层出现一次。Boss 血量更高、奖励更好。如果玩家暂时打不过 Boss，可以回到已解锁的普通层刷资源。

第一版包含：

- 自动攻击。
- 点击攻击。
- 敌人血条。
- 基础伤害反馈。
- 普通怪。
- Boss 怪。
- 最近掉落记录。

## 角色成长系统

玩家角色拥有以下属性：

- 等级。
- 经验。
- 金币。
- 攻击力。
- 生命值。
- 暴击率。
- 暴击伤害。
- 攻击速度。

金币用于直接升级属性。经验用于提升角色等级，并提供长期成长。MVP 的公式应保持清晰、可调整，不追求复杂数值系统。

## 装备系统

第一版采用轻量装备系统，但数据结构预留后续暗黑词条扩展。

装备部位：

- 武器。
- 护甲。
- 饰品。

装备字段：

- 唯一 id。
- 名称。
- 部位。
- 稀有度。
- 装备等级。
- 主属性。
- 副属性。
- 预留词条数组。
- 预留特殊效果字段。

MVP 支持：

- 怪物掉落装备。
- 装备稀有度。
- 基础属性比较。
- 穿戴装备。
- 背包列表。
- 一键装备更强装备。

MVP 暂不包含：

- 打造。
- 洗练。
- 套装。
- 传奇特效。
- 复杂词条池。

## 技能系统

第一版有 3 个主动技能：

- 爆发伤害：造成一次高额即时伤害。
- 急速：短时间提升攻击速度。
- 幸运：短时间提升金币收益或掉落概率。

每个技能包含：

- 等级。
- 冷却时间。
- 效果数值。
- 升级消耗。

技能由玩家手动释放。后续版本可以加入被动技能、技能树或自动释放。

## 地下城推进

地下城按层数推进。普通层用于稳定刷怪，Boss 层用于控制进度门槛。更高层数会提升怪物生命、奖励和装备等级。

MVP 需要保存：

- 当前层数。
- 已解锁最高层数。
- 最高稳定刷怪层数。
- Boss 进度状态。

最高稳定刷怪层数用于离线收益计算，避免离线收益按玩家尚不能稳定击杀的 Boss 层结算。

## 离线收益

离线收益最多累计 8 小时。

玩家打开游戏时：

1. 读取上次保存时间。
2. 计算离线时长。
3. 将离线时长限制在 8 小时以内。
4. 按最高稳定刷怪层数估算金币和经验。
5. 以低于在线刷怪的概率生成少量装备。
6. 显示离线收益结算面板。
7. 保存更新后的游戏状态。

离线收益应当有存在感，但不能优于在线参与。

## 存档系统

MVP 使用本地自动保存。

存档数据包括：

- 存档结构版本号。
- 角色状态。
- 金币和经验。
- 当前层数和最高层数。
- 已装备装备。
- 背包装备。
- 技能等级。
- 设置项。
- 上次保存时间。

导入/导出存档码是必需功能，用于跨设备迁移。

导出流程：

1. 将存档数据序列化为 JSON。
2. 编码为一段较紧凑的文本存档码。
3. 显示存档码，供玩家复制。

导入流程：

1. 接收玩家输入的存档码。
2. 解码存档码。
3. 校验版本号和必要字段。
4. 成功后覆盖本地存档。
5. 输入无效时显示清晰错误。

存档必须包含 `schemaVersion`，方便后续做数据迁移。

## 界面结构

手机端使用底部标签式 App 结构。电脑端使用同一套导航信息，但展示为侧边导航。

主要页面：

- 战斗：默认首页，显示敌人、血条、点击区域、技能按钮、当前层数、收益速度和最近掉落。
- 装备：显示已装备物品、背包、装备对比和装备操作。
- 技能：显示主动技能、冷却、效果和升级按钮。
- 地下城：显示当前进度、Boss 节点、最高解锁层数和刷怪层选择。
- 角色：显示等级、金币、经验、属性和属性升级。
- 设置：显示自动保存状态、导出存档、导入存档和重置存档。

手机端设计重点：

- 战斗点击区域要足够大。
- 底部导航固定。
- 主要操作适合单手触摸。
- 避免过密的并排面板。

电脑端设计重点：

- 使用左侧导航。
- 战斗区域更宽。
- 战斗信息和最近掉落可以并排展示。

## 技术架构

推荐技术栈：

- React。
- TypeScript。
- Vite。
- Zustand 或类似的轻量状态管理。
- CSS 或 CSS Modules 做响应式样式。
- Vitest 测试纯游戏逻辑。
- 网页 MVP 可玩后再接入 Capacitor。

建议目录结构：

```text
src/
  app/
  features/
  game/
  store/
  styles/
```

职责划分：

- `src/app/`：响应式应用外壳、导航和整体布局。
- `src/features/`：战斗、装备、技能、地下城、角色、设置等页面。
- `src/game/`：纯游戏逻辑，包括公式、战斗 tick、装备生成、离线收益、存档校验。
- `src/store/`：全局游戏状态和操作方法。
- `src/styles/`：全局样式、主题和布局规则。

`src/game/` 中的逻辑不能依赖 React。这样公式更容易测试，未来迁移平台也更容易。

## 测试策略

优先测试高风险的纯逻辑：

- 伤害计算。
- 暴击计算。
- 怪物随层数成长。
- 装备生成。
- 装备比较。
- 技能升级消耗。
- 离线收益上限和收益计算。
- 存档导入/导出校验。
- 存档结构迁移钩子。

UI 测试可以在 MVP 主流程成型后再补。早期需要手动验证电脑和手机视口下的布局。

## MVP 验收标准

MVP 完成时应满足：

- 玩家可以自动战斗。
- 玩家可以点击敌人造成额外伤害。
- 普通怪和 Boss 可以被击败。
- 玩家可以获得金币、经验和装备。
- 玩家可以升级角色属性和技能。
- 玩家可以查看、比较和穿戴装备。
- 地下城层数可以推进。
- 本地自动保存可用。
- 存档码导出和导入可用。
- 离线收益最多按 8 小时结算。
- 界面在电脑和手机视口下都可用。

## 后续扩展

后续可以考虑：

- 云存档和账号登录。
- 手机 App 打包和应用商店准备。
- 更丰富的词条池。
- 传奇装备特效。
- 套装效果。
- 打造和洗练。
- 被动技能树。
- 每日或每周挑战。
- 更多地下城区域。
- 成就和收集系统。
